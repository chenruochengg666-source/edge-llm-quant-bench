# ARC-Challenge 补充实验操作说明

**目的**：回应审稿意见第（3）条——ARC-Easy 作为主判据的代表性不足。

---

## 一、为什么选 ARC-Challenge

| 项 | ARC-Easy | ARC-Challenge |
|---|---|---|
| 题量 | 2376 | **1172** |
| 难度 | 含检索/词共现可解题 | **过滤后只留需推理的题** |
| 来源 | 同一数据集（AI2 ARC） | 同一数据集 |
| 补充成本 | — | **最低**（同源，换题库即可） |
| 对照价值 | — | **最直接**（同模型、同流程、只换判据） |

**核心逻辑**：如果在 ARC-Challenge 上"沉默区"变成"同步退化区"，说明 ARC-Easy 低估了量化对推理能力的损害——这本身就是一个有价值的发现。

## 二、三步操作

### 第 1 步：准备数据（约 5 分钟）

```bash
pip install datasets
python prepare_arc_challenge.py
```

**输出**：`03_data/arc/ARC-Challenge-test-full.jsonl`（1172 题）

**若无法访问 HuggingFace**：

```bash
# Windows
set HF_ENDPOINT=https://hf-mirror.com
# Linux / WSL
export HF_ENDPOINT=https://hf-mirror.com
```

### 第 2 步：跑评测（约 3~6 小时，视模型数）

```bash
python run_arc_challenge.py
```

**注意**：
- 脚本会自动遍历 `02_gguf/quantized` 下所有 `.gguf` 文件
- **想只跑关键档位，就临时把其他 gguf 移出目录**
- 支持续跑（已完成的题会跳过，可中断后重跑）
- 输出在 `05_raw/arc_challenge/`，**不覆盖原 ARC-Easy 数据**

**建议先只跑两个模型的关键档位**（导师建议）：
- Qwen2.5-1.5B：FP16 / Q4_K_M / Q3_K_M / Q2_K
- Llama-3.2-1B：FP16 / Q4_K_M / Q2_K

**这两个模型是"沉默区"结论的关键证据来源。**

### 第 3 步：对比分析（约 1 分钟）

```bash
python compare_easy_challenge.py
```

**输出**：`06_results/arc_easy_vs_challenge.csv`

**对照表形如**：

| 模型文件 | Easy准确率 | Challenge准确率 | 差值(pp) |
|---|---|---|---|
| qwen2.5-1.5b-q4_k_m.gguf | 85.19 | ? | ? |
| ll32-q4_k_m.gguf | 12.36 | ? | ? |

## 三、三种可能结果与对应写法

### 结果 A：两套题库结论一致

**写作**：
> 补充 ARC-Challenge 后，各档位的区间归属与基于 ARC-Easy 的判定完全一致，说明原结论对该判据选择不敏感，稳健性得到验证。

**价值**：增强稳健性。

### 结果 B：沉默区 → 同步退化区（最有价值）

**例如**：Llama-1B Q4_K_M 在 Easy 上 ARC 从 37.41 降到 12.36（沉默区），若在 Challenge 上降幅更大且统计显著，则升级为同步退化区。

**写作**：
> 在 ARC-Challenge 上，Llama-1B 的 Q4_K_M 由"沉默区"升级为"同步退化区"。这表明 ARC-Easy 因包含检索类易解题，系统性掩盖了量化对推理能力的损害。本文据此修正结论：**浅层基准会低估量化风险，沉默区的危险程度在推理密集型任务上更为严重。**

**价值**：**把审稿人的批评转化为新发现**——这是最理想的回应方式。

### 结果 C：出现新的反升或反转

**写作**：需逐题分析，说明为何在 Challenge 上出现不同方向。可能是样本量下降（1172 vs 2376）导致的统计波动，也可能是任务难度差异导致的真实差异。

**价值**：需要额外解释，但也是实质内容。

## 六、注意事项

| 项 | 说明 |
|---|---|
| **不要改 prompt 格式** | 与 ARC-Easy 评测时完全一致，否则不可比 |
| **不要改采样参数** | temperature=0、top_p=1、seed=42 |
| **续跑机制** | 中断后重跑会跳过已完成题，安全 |
| **f16 档** | 脚本对 f16 放宽了 max_tokens（64），保持原逻辑 |
| **服务失败题** | pred 为空的行会被跳过，与论文"有效样本"口径一致 |
